# Notes for Claude

This repo is Dave Nab's website, live at https://davenab.com (custom domain via the `CNAME` file; https://davenab.github.io redirects there). It is published by GitHub Pages from `main` (root). Cloudflare holds the DNS.

## Publishing changes
- Dave wants changes to go live without merging them himself: after making and testing a change, open a pull request and merge it into `main` straight away (GitHub Pages then publishes it in a few minutes). Tell Dave what went live and give the pull request link.
- Do not merge if a test fails or a change needs Dave's decision first (e.g. deleting content, paid items, anything unclear): ask him instead.

## Site pages (main website)
- Pages: `/` (home), `/apps/`, `/resources/`, `/ielts-courses/`, `/ielts-mock-test/`, `/general-english/` (+ `speaking-fluency/`, `level-up/`), `/testimonials/`, `/gallery/`, `/about/`, `/book/`.
- These pages are GENERATED by `_tools/build.py` (shared nav, footer and all page content). To change any of them, edit `_tools/build.py`, run `python3 _tools/build.py .` from the repo root, and commit the regenerated HTML. Never hand-edit only one generated page: the next build overwrites it. Deployment has no build step: the committed HTML is what's served.
- Styles: `/assets/style.css` (colour tokens on `:root`, dark mode via `prefers-color-scheme` + `data-theme`). Behaviour: `/assets/app.js` (theme toggle, nav, scroll reveals, carousel, lightbox, `data-f`/`data-cat` filters). Booking form: `/assets/book.js`. Images: `/assets/img/` (WebP).
- Generated pages use relative links (e.g. `../about/`) so they also work in previews.
- Design: navy ink + amber accent + skill colours. Yellow `#FFFF00` (`--sun`) is used ONLY for the DN logo, highlighter swipes, the scroll-progress bar, text selection and tiny dots. Dave asked for headings that aren't too large.
- Home page order (6 sections, keep it short): hero with a "Who are you?" chooser (student / teacher / book) → AI apps (main focus) → resources (students/teachers) → courses → testimonials → contact. The stats, the scrolling statement and the photo strip live on `/about/`.
- Every page ends with a "Keep exploring" strip: internal links plus a few useful outside links (official IELTS, British Council, Academic Phrasebank, etc.), set per page in `RELATED` in `_tools/build.py`.
- `404.html` is generated with root-absolute links (GitHub Pages serves it at any depth); it suggests a page based on words in the address.
- Share image for every page: `/assets/og/davenab-share.png` (1200×630), added automatically by `page()` unless a page sets its own `og:image`.
- Phone header shows a small "Book" button next to the menu.

## AI feedback (Cloudflare Worker davenab-api, https://api.davenab.com)
- Routes: `/feedback` (hubs' Use it step), `/coach` (Feedback Coach; only accepts prompts starting "You are the Feedback-to-Mastery Coach"), `/gsc` (Grammar Self-Correction Trainer "My own writing": marks errors with codes, positions computed server-side), `/rewrite` (Nominalisation & Hedging + APA Trainer rewrite questions), `/notes` (Notetaking Trainer: AI check of typed notes vs key ideas), `/dictogloss` (Dictogloss Trainer), `/e` + `/stats` (anonymous hub scores).
- Apps call the Worker through the shared helper `/assets/ai.js` (`DNAI.post(route, payload, {app})`: 20 s timeout, 10 requests per hour per device per app, plain-language error messages). New apps that need AI feedback should use it and get their own route + daily cap in `worker.js`. AI is always optional: the student presses a button, and the app still works without it.
- Model: `@cf/google/gemma-4-26b-a4b-it` with thinking off (fast, ~10x cheaper than Llama 70B). Daily caps per route (`CAP_FEEDBACK` 250, `CAP_COACH` 200, `CAP_GSC` 120, `CAP_REWRITE` 150, `CAP_NOTES` 80, `CAP_DICTO` 120) keep usage inside the free 10,000 neurons/day; the free plan never charges. Student text is never stored or logged.
- Redeploying: edit `_tools/cloudflare/worker.js`, then upload it with the Cloudflare API connector (keep all bindings and variables; see SETUP.md).

## Apps
- Style and build rules for apps: `_tools/APP-STYLE-GUIDE.md` (follow it for every new app).
- Every app loads `/assets/appbar.js`: a slim "DN Dave Nab · All apps · Resources" bar, plus `DNNext.html("<app-id>")` for the "What next?" box on the finish screen. Add new apps to `APPS`/`NEXT` in that file.
- Each app is a self-contained static page in its own folder: `/<slug>/index.html`. No backend, no API keys in the code (the repo is public).
- Apps must work without sign-in on laptops and phones, keep student data on the device (localStorage at most), and support light/dark mode.
- Live apps: `/note-taking-trainer-ted/` (Notetaking Trainer, TED edition; optional AI notes check on the self-check step; `/note-taking-trainer/` is now a redirect to it) `/grammar-self-correction/` (Grammar Self-Correction Trainer) and `/nominalisation-hedging-trainer/` (Nominalisation and Hedging Trainer; items in its `data/*.json`). Some apps load `/assets/site.js` (legacy theme toggle): keep that file.
- Live apps are listed first in `APPS` in `_tools/build.py` so they lead the AI section on the home page.
- When an app goes live, add it to `LIVE` in `_tools/build.py` (title → folder), rebuild, and add it to `/sitemap.xml`. Card skills: listen, read, write, gram, vocab.
- **Feedback-to-Mastery Coach** `/feedback-coach/` (live since Nov 2026). Its answer checking is deliberately strict (meaning check first; "when torn, choose the lower level"), in `gradeAnswer` in `app.html`. An AI tutor that turns teacher feedback into lessons. Source: `_tools/feedback-coach/curriculum.js` (vetted lessons) + `app.html` (app). `python3 _tools/build.py .` assembles them into `/feedback-coach/index.html` in website mode (`assemble_coach`, `COACH_API`): AI goes to the Worker route `/coach`, no sign-in. `COACH_BAND` (default False) adds the big featured band on the home page. The old Claude artifact (`COACH_URL`, `coach.html` = app.html with the curriculum pasted in) still works in Claude mode if republished.
- APA Trainer `/apa-citation-trainer/` (in-text citation drills; items in `data/track-*.json`) and APA Reference Guide `/apa-reference-guide/` (searchable reference-list patterns; content in `data/sources.json`, patterns from the UTS APA 7th guide). The guide reuses APA Trainer's `style.css`.
- **Grammar Hub** `/grammar-hub/` and **Vocabulary Hub** `/vocabulary-hub/` (live since Nov 2026). One shared engine in `/assets/hub/` (`hub.js`, `hub.css`, `config.js`); each hub's units are in its `data/units.json` (unit = pre test, notice text with `[[targets]]`, discover questions, rule card, practice, post test, produce task; vocab units also have `words`). Every unit follows test–teach–test with noticing and guided discovery (Try it → Notice → Work it out → Practise → Try again → Use it), with spaced review (1/3/7 days) of missed items. All units are `"verified": false` (shows "Draft content") until Dave checks them; `#/check` lists every answer for him. Item types: mcq, gap, fix (`{wrong}` word), order, sort, match.
- Hub data and AI: `assets/hub/config.js` `apiBase` = `https://api.davenab.com`, the Cloudflare Worker `davenab-api` (deployed 22 Nov 2026; code and setup in `_tools/cloudflare/`, see `SETUP.md`; D1 database `davenab-db`). Empty = off. To change the Worker, edit `_tools/cloudflare/worker.js` and redeploy (the Cloudflare API connector can upload it). Impact summary: https://api.davenab.com/stats. When on: opt-in anonymous score sharing (month, hub, unit, level, pre, post only; no IDs or IPs) and "Get AI feedback" on the Use it step (Workers AI, daily cap). This is the one approved exception to "no tracking in apps".
- **Dictogloss Trainer** `/dictogloss/` (live since Nov 2026): 12 passages in `data/passages/*.json` (all `"verified": false` until Dave checks them; list in `data/index.json`), audio = MP3 in `audio/` if `audioFile` is set, otherwise browser speech synthesis (en-AU/en-GB preferred). Live feedback via `/assets/ai.js` → Worker `/dictogloss` (twice per session max; self-check fallback). Printable scripts: `scripts.html`. No analytics: it sets `window.DN_NO_BEACON = true` before `appbar.js`. See its README for adding passages/recordings.
- Planned apps: skim-and-scan timer, paragraph X-ray, synthesis builder, register swapper.
